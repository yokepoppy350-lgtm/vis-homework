LESSON01

页面骨架与视觉层级

Structure & Hierarchy

页面布局的第一步不是选颜色，而是先决定“哪些内容属于同一区域、它们按照什么顺序出现”。

先分区，再摆元素

先把页面拆成 header、nav、main、aside、section、footer 等区域，再考虑每个区域内部的排版。这样做能先解决“结构”，避免一开始就陷入字体、颜色和按钮细节。

判断标准：同一任务、同一语义、同一视觉层级的内容，应尽量放在同一区域。

正常文档流是默认起点

块级元素默认从上到下排列，这就是 Normal Flow。一个可靠的页面应当在不使用绝对定位时仍然保持基本可读；绝对定位适合局部装饰，不适合承担整页布局。

DOM 顺序还会影响键盘访问、屏幕阅读器和移动端重排，因此“视觉顺序”最好与“文档顺序”一致。

用容器控制阅读宽度

正文直接铺满超宽屏会导致视线移动距离过大。常见做法是给主内容设置 max-width，再用 margin-inline:auto 居中；外层负责背景，内层负责内容宽度。

层级来自四件事

字号、字重、间距和对齐共同决定层级。标题不一定要“特别大”，只要和正文形成稳定差异即可。相比不断增加颜色，留白通常是更可靠的分组手段。

布局顺序

结构 → 尺寸 → 间距 → 对齐 → 颜色与装饰。如果结构尚未稳定就先做视觉装饰，后期往往需要反复推翻。

KEY IMPLEMENTATION

语义结构 + 居中容器

让 HTML 结构表达页面含义，再让 CSS 决定区域的位置和尺寸。

<header class="site-header">...</header>
<main class="page-shell">
  <aside class="sidebar">...</aside>
  <section class="content">...</section>
</main>
<footer class="site-footer">...</footer>

.page-shell {
  width: min(1200px, calc(100% - 40px));
  margin-inline: auto;
  display: grid;
  grid-template-columns: 220px minmax(0, 1fr);
  gap: 24px;
}
为什么这么写？

minmax(0,1fr) 允许内容列真正收缩，避免长文本或图表把 Grid 撑破。

常见错误

为了“摆到某个位置”大量使用 position:absolute，页面一改尺寸就全部错位。

LESSON02

盒模型与间距系统

Box Model & Spacing

页面里的每个元素都是一个盒子。理解 content、padding、border 和 margin，才能真正控制尺寸与留白。

盒模型的四层

从内到外依次是 content → padding → border → margin。Padding 属于组件内部空间，Margin 用来建立组件之间的距离，两者视觉上都像“空白”，但语义不同。

优先使用 border-box

默认的 content-box 会把 padding 和 border 加到 width 之外。设置 box-sizing:border-box 后，声明的宽度就是元素最终占据的边框尺寸，更容易计算卡片和列宽。

建立统一间距尺度

不要在页面里随意出现 13px、17px、29px。可以采用 4px 或 8px 为基础的间距系统，例如 4 / 8 / 12 / 16 / 24 / 32 / 48，让不同组件之间的节奏更一致。

处理溢出与最小宽度

Grid/Flex 子项里常见的“内容把容器撑破”问题，往往不是父布局错误，而是子项默认 min-width:auto。对内容列设置 min-width:0，再配合 overflow 控制溢出。

间距判断

如果空白属于“这个组件自身”，用 padding；如果空白表达“两个组件之间的关系”，用 gap 或 margin。布局容器内部优先使用 gap，可读性通常更好。

KEY IMPLEMENTATION

全局盒模型 + 间距变量

统一盒模型，并用 CSS 变量减少随意的间距数字。

*, *::before, *::after {
  box-sizing: border-box;
}

:root {
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-6: 24px;
  --space-8: 32px;
}

.card {
  padding: var(--space-6);
  border: 1px solid #e5e7eb;
  border-radius: 12px;
}
为什么这么写？

统一间距令页面更像一个系统，而不是多个独立组件临时拼在一起。

常见错误

把 margin 当成“移动元素”的工具，导致相邻元素出现不可预测的间距和 margin collapse。

LESSON03

Flexbox：一维弹性布局

One-dimensional Layout

当主要问题是“这一行”或“这一列里的元素怎么排列”时，Flexbox 通常是最直接的工具。

主轴与交叉轴

flex-direction 决定主轴方向。justify-content 管主轴上的分配，align-items 管交叉轴上的对齐。先判断主轴，Flexbox 的大部分属性就不容易混淆。

用 gap 管理成员间距

导航、工具栏、按钮组等组件内部的元素间距，优先使用 gap。它不会给容器首尾额外增加空白，也不需要给第一个/最后一个元素单独清除 margin。

grow、shrink 与 basis

flex: grow shrink basis 决定元素如何分配剩余空间。常用的 flex:1 可以让兄弟元素平分剩余空间；固定侧栏则可以使用 flex:0 0 220px。

需要换行时开启 wrap

标签组、卡片列表在空间不足时可以使用 flex-wrap:wrap。如果你需要同时严格控制“行”和“列”，通常应考虑 Grid 而不是继续堆 Flex。

什么时候用 Flex？

导航栏、按钮组、工具栏、单行卡片、图例、标题与操作区等一维排列最适合 Flexbox。

KEY IMPLEMENTATION

主轴分配 + 交叉轴对齐

少量属性即可完成大多数工具栏和导航布局。

.toolbar {
  display: flex;
  flex-direction: row;
  justify-content: space-between;
  align-items: center;
  gap: 16px;
}

.toolbar__search { flex: 1 1 320px; }
.toolbar__actions { flex: 0 0 auto; }
为什么这么写？

搜索框可以伸缩，操作按钮保持自身宽度，空间变化时行为清晰。

常见错误

不理解主轴就不断切换 justify/align；或者给每个子项硬编码宽度，失去 Flex 的弹性。

LESSON04

CSS Grid：二维网格布局

Two-dimensional Layout

当页面需要同时规划“几列”和“几行”，或者要搭建 Dashboard 主骨架时，Grid 比 Flexbox 更合适。

列和行一起规划

Grid 容器通过 grid-template-columns 和 grid-template-rows 建立轨道。子项可以自动进入格子，也可以跨越多列/多行。

fr 表示“剩余空间份额”

1fr 2fr 并不是绝对宽度，而是将可分配空间按 1:2 分配。配合固定侧栏可写成 220px minmax(0,1fr)。

repeat 与 minmax

repeat() 减少重复声明；minmax() 给轨道设置上下限。卡片列表常用 repeat(auto-fit,minmax(220px,1fr)) 自动决定列数。

Grid Areas 适合表达页面结构

对于 header / sidebar / main / footer 这类稳定区域，grid-template-areas 可直接用名字描述布局，代码更接近设计草图。

Flex 还是 Grid？

只关心一个方向，用 Flex；需要同时控制行列或组件跨区，用 Grid。两者不是竞争关系，真实页面通常会嵌套使用。

KEY IMPLEMENTATION

自适应卡片网格

不用写多个断点，也能根据可用宽度自动改变列数。

.card-grid {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(220px, 1fr));
  gap: 20px;
}

.dashboard {
  display: grid;
  grid-template-columns: 2fr 1fr;
  gap: 24px;
}
为什么这么写？

auto-fit + minmax 让卡片尽量填满一行，同时保证单卡不会小到难读。

常见错误

为了做三列直接给每张卡 width:33.333%，再叠加 gap 后发生溢出。

LESSON05

响应式布局

Responsive Design

响应式不是把桌面页面整体缩小，而是根据空间重新组织内容、改变列数和优先级。

断点由内容决定

不要机械地只记 768px、1024px。真正的断点应该出现在“当前布局开始拥挤或失去可读性”的位置。先缩窄页面观察，再决定何时重排。

Mobile First

先写最简单的单列布局，再用 min-width 媒体查询逐步增强。这样默认样式更轻，也更容易保证小屏可用。

流式尺寸与 clamp

clamp(min, preferred, max) 可以让字体、间距和容器尺寸在区间内平滑变化，减少“每个尺寸都写一个断点”的需求。

重排优于缩放

桌面端的“侧栏 + 两列图表”到了手机上，应变成“顶部导航 + 单列图表”，而不是把整张页面压缩到 40% 导致文字无法阅读。

响应式检查清单

检查导航是否可操作、正文是否仍可读、图表是否溢出、控件是否有足够触控面积、重要信息是否仍排在前面。

KEY IMPLEMENTATION

Mobile First + 自适应列

先保证小屏单列，再在空间足够时升级为多列。

.cards {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}

.title {
  font-size: clamp(24px, 3vw, 40px);
}

@media (min-width: 720px) {
  .cards { grid-template-columns: repeat(2, 1fr); }
}

@media (min-width: 1080px) {
  .cards { grid-template-columns: repeat(3, 1fr); }
}
为什么这么写？

默认规则适合小屏，浏览器只在更宽时追加增强样式，逻辑更清楚。

常见错误

只改列数，不检查字体、内边距、按钮尺寸和长文本，导致布局“没溢出但很难用”。

LESSON06

综合案例：可视化 Dashboard 布局

Layout Composition

把前五节组合起来：用语义结构确定区域，用 Grid 搭骨架，用 Flex 排内部组件，再用响应式规则完成不同屏幕的重排。

第一步：画区域草图

先只画 Header、Sidebar、Summary、Main Chart、Secondary Chart 等大区块，不画具体内容。目标是确定信息优先级和阅读路径。

第二步：选择布局工具

页面主骨架使用 Grid；顶部工具栏、筛选项、图例等局部一维结构使用 Flex；每张卡片内部再回到正常文档流。

第三步：限制尺寸

给侧栏、卡片最小宽度、图表最小高度设置合理约束。布局不是“让所有东西都能缩”，而是定义哪些能缩、哪些要换行、哪些需要隐藏或移动。

第四步：设计响应式降级

桌面端可以同时显示更多辅助信息；平板减少列数；手机端保留关键指标和主图，将次要内容向下排列。不同尺寸保持信息意义一致，而不是视觉形式完全一致。

第五步：用线框测试，再做美化

先打开边界线和区域标签，检查布局关系；确认没有溢出、错位和不合理留白后，再加入颜色、阴影、圆角和图表细节。

最终原则

好的页面布局应同时满足：层级清晰、空间稳定、组件可复用、尺寸可适配、代码可维护。美观来自这些规则的一致执行，而不是单独某个颜色或圆角。

KEY IMPLEMENTATION

Grid 骨架 + 响应式重排

桌面两列，移动端改单列；内部的小组件继续使用 Flex。

.dashboard {
  display: grid;
  grid-template-columns: 220px minmax(0, 1fr);
  grid-template-areas:
    "sidebar header"
    "sidebar main";
  min-height: 100vh;
}

.dashboard-main {
  display: grid;
  grid-template-columns: 2fr 1fr;
  gap: 20px;
}

@media (max-width: 760px) {
  .dashboard {
    grid-template-columns: 1fr;
    grid-template-areas: "header" "main";
  }
  .sidebar { display: none; }
  .dashboard-main { grid-template-columns: 1fr; }
}
为什么这么写？

主区域的关系直接写在 Grid 中，局部组件则保持独立，后续修改某张卡片不会破坏整页。

常见错误

桌面、平板、手机分别写三套完全不同的 DOM，维护成本高；更好的方法是复用结构，只改变布局规则。
